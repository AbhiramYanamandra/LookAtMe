## Overview

A pipelined, MIPS-style processor split into the classic five stages — **Fetch, Decode, Execute, Memory, and Writeback** — with pipeline registers between each stage so several instructions are in flight at once.

## The BNE extension

The base design was extended to support the **Branch Not Equal (BNE)** instruction, which requires the branch-decision logic to act on the ALU's comparison result and steer the program counter accordingly.

## About the diagram

The datapath diagram at the top of this page is the **standard textbook five-stage pipeline** with its control signals. It is shown to explain the architecture the project follows; it is not the project’s own schematic or a simulation screenshot. The simplified five-box illustration on the homepage card is likewise an explanatory graphic, not implementation evidence.

## Hazard handling

A pipeline is only correct once it handles instructions that depend on each other.

**Forwarding** logic detects source/destination dependencies and routes results from MEM and WB directly back into EX. In the documented simulation, a dependent add consumes the forwarded value — `8` — without stalling for write-back.

**Flushing** handles control hazards: branch and tag-mismatch logic replaces wrong-path instructions with NOPs, which is what prevents invalid writes reaching tally memory when a branch resolves the other way.

## On hardware

The design is written in **VHDL**, synthesised in **Vivado**, and implemented on a **Basys-3 (Artix-7)** board, driven interactively through switches, buttons and the seven-segment display.

It is small: **334 LUTs (1.61%)** and **393 flip-flops (0.94%)**, with I/O the binding constraint at **49 pins (46.23%)** — a processor whose cost is dominated by talking to the outside world rather than by computing.
